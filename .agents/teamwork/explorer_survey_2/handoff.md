## 2. Logic Chain

1. **R3 (Black Screen Root Cause)**:
   - Observation 1 shows `splashscreen.xml` lacks the logo bitmap and is a blank `#0b1110` background.
   - Observation 2 shows `MainActivity.kt` switches the window theme to `AppTheme` (`#09090b`) immediately on activity creation.
   - Observation 3 shows no native splash overlay is retained via `expo-splash-screen`.
   - Observation 4 shows `MainApplication.kt` blocks the main UI thread with synchronous file deletions.
   - Observation 5 shows the 3.6 MB bundle delivered via OTA or embedded bundling is plaintext JS rather than compiled Hermes bytecode. Because Hermes has no JIT, it must parse and compile 3.6 MB in RAM on the device's CPU. On low-spec hardware (Galaxy Tab A 2016, 1.5GB RAM, Cortex-A53), this CPU and RAM exhaustion delays the first React Native paint by 5 to 10+ seconds.
   - Observations 6 & 7 show that monolithic eager evaluation and uncoordinated network/AsyncStorage/FileSystem storms further stall the JS thread.
   - *Therefore*: The user sees a solid black screen (`#09090b`) for 5–10 seconds because the native splash theme is stripped at Activity start while Hermes spends seconds compiling the unoptimized 3.6 MB plaintext bundle under high RAM pressure.

2. **R5 (Content Flickering & Alternate Albums Root Cause)**:
   - Observations 8 & 9 establish that `HomeScreen` mounts with `INITIAL_ALBUMS` and `INITIAL_TRACKS`, immediately painting the 4 hardcoded placeholder albums on Frame 0.
   - Observation 10 shows that local cache hydration from `AsyncStorage` is artificially deferred by `setTimeout(0)`. When it completes (Frame 1), `setAlbums(cached)` suddenly replaces the dummy albums with cached albums, causing the first layout shift and cover flash.
   - Observation 11 shows that when remote network requests `/api/tracks` and `/api/albums` return (Frame 2), `setAlbums(remote)` and `setTracks(remote)` fire again, causing a second layout shift.
   - *Therefore*: The visual flickering and "alternate albums" flash is caused by an uncoordinated 4-stage cascade: Hardcoded Placeholders (Frame 0) → AsyncStorage cache via `setTimeout(0)` (Frame 1) → Remote Tracks/Albums (Frame 2) → Remote User Data / Playlists (Frame 3).

## 4. Conclusion

1. **Root Cause of R3 (Cold Start Black Screen)**:
   - Premature window theme switch in `MainActivity.kt` to `#09090b` without `expo-splash-screen` native view lock.
   - Omission of `splashscreen_image` in `drawable/splashscreen.xml`.
   - Synchronous disk I/O in `MainApplication.kt:cleanupOldInstallers()`.
   - Missing Hermes bytecode (`hermesc`) compilation in `scripts/publish-ota.js` and `package.json`, causing 3.6 MB of plaintext JS to be compiled in RAM on 1.5GB RAM hardware.
   - Monolithic imports in `App.js` and uncontrolled boot I/O storm.

2. **Root Cause of R5 (Content Layout Stability & Flickering)**:
   - Hardcoded `INITIAL_ALBUMS` and `INITIAL_TRACKS` in `UserContext.js` rendered by `HomeScreen.js` on Frame 0.
   - Asynchronous cache hydration pushed into `setTimeout(..., 0)`.
   - Multi-phase re-render cascade: Placeholders → Cache → API Tracks/Albums → API User Data.
